# Code style

## Язык

Человеческий текст в проекте — на русском: комментарии в коде, docstring и doc-комментарии, сообщения коммитов, заголовки PR, документация. Идентификаторы кода (типы, функции, переменные) — латиницей, как во всём проекте (`Service`, `Book`, `Cell`).

У публичных сервисов и остальных точек публичного API — docstring с описанием контракта: что делает, что принимает, что возвращает (Python — docstring, Rust — `///`). Стиль докстрингов — как в `core_pyo3/python/report_core/_report_core.pyi`.

В докстрингах публичного API — никаких ссылок на issues и жаргонных помет в скобках: они попадают в описание метода/функции в `.pyi`-стабы. Такие детали живут в комментариях кода, тестах и сообщении коммита.

## Числа

Числа в бизнес-логике — только именованные константы или настройки; магических чисел в коде не оставляй. Тривиальные `0`/`1` (пустой индекс, единичный шаг) допустимы. Константы по умолчанию объявляй на уровне модуля с поясняющим комментарием — как `DEFAULT_COLUMN_WIDTH` / `DEFAULT_ROW_HEIGHT`.

## Практики

- Формат решает инструмент: `cargo fmt` для Rust, `ruff` для Python; вручную форматирование не правим.
- Держим идиомы языка: Rust — подсказки clippy (гейт гоняет с `-D warnings`), Python — то, что покрывает `ruff check`.
- Изменения точечные: один PR — одна задача (см. `docs/agents/git-workflow.md`); попутные переименования и реформаты не подмешиваем.
